# 中文整理怎么运行

首页默认显示中文标题和一段概括。点击标题直接打开原文；英文原题和来源短摘要也保留在资料中，可以核对。当前222条有效资料均已整理为中文，期刊封面和目录等3条非文章记录已排除。

## 每段中文依据什么

| 依据类型 | 本轮条数 | 可以写到哪里 |
| --- | --- | --- |
| abstract：论文摘要 | 44 | 依据实际提供的完整摘要，概括研究问题、方法和材料支持的结果；不称为读过论文全文 |
| source_excerpt：来源节选 | 67 | 依据机构新闻或RSS的实质摘要、节选概括；不补全被截断的句子 |
| title_only：只有标题 | 111 | 只说明标题能确认的主题，明确提醒“来源未提供摘要，具体方法与结果需查看原文” |

只有作者、单位、DOI或目录等元数据时，也归为“只有标题”。本轮有10条因此保守降级，没有把这些文字当成研究发现。中文整理属于翻译与概括，不代表科学事实已核验，也不等于完整 AIHOT 的两次选稿评分。

## 已经执行的部分

本轮由当前聊天中的 AI 助手实际执行 [中文整理提示词](../prompts/chinese-reader.md)，读取可得的论文摘要、来源节选或标题。结果保存在 [中文整理文件](../config/chinese-editorial.json)，包括条目编号、输入指纹、中文标题、概括段落和依据类型；有额外取证时保留取证时间与材料摘要指纹。

整理文件有225份历史结果，其中3份对应后来剔除的非文章记录；当前阅读页只应用222份有效结果。首轮 GitHub 采集新增的一条 Mongabay 珊瑚资料，也已由 AI 助手依据来源节选补齐中文。没有将未发表、未核实的推断补成结论，也没有在仓库中存放模型 API 密钥。

## 以后更新会发生什么

1. “更新订阅.cmd”或GitHub更新流程抓取公开来源，执行判重和规则筛选。
2. 原题及240字来源短摘要的输入指纹仍一致时，继续使用已保存的中文结果。
3. 新资料或输入变化的资料进入待整理队列，旧中文概括不会自动套上去。
4. 首页默认只显示已整理中文，勾选“也看待整理原文”可以查看队列中的原始资料。中文RSS也只输出已整理条目，最多最新200条。
5. 需要继续中文整理时，让 AI 助手使用同一份提示词处理待整理资料，再更新结果文件并重建阅读数据。

这套方式先让现有资料能方便地阅读，同时把模型整理与定时采集分开。**当前没有无人值守的自动翻译服务**；定时任务成功，表示完成采集和应用已有结果，不表示所有新资料都已翻译。
