
【标题自洽规则 — 让读者不点开就知道"这是关于谁、在哪个海区、做了什么"】

1. 标题必须点出核心主体：模式/卫星/数据集名 / 机构名 / 航次或项目名，能点名海区时点出标准中文海区名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "v2.1.159"、"Small is a feature"、"Day 1"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "GLORYS12V1 release notes" + 来源 "Copernicus Marine" → "Copernicus Marine 发布 GLORYS12V1 再分析产品"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体型号时，用上位词（如"一套全球再分析产品"）兜底，绝不凭"领域常识"编一个具体型号 / 版本 / 数字 / 海区。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Assessment 这类解释、分析、教程或评估标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的模式、数据集或政策，就改写成“发布 / 推出 / 开放 / 签署”。只有原标题明确宣布了发布、推出、开放或签署，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的机构、模式、数据或项目名。
   例：原标题 "How SWOT altimetry improves coastal sea level estimates" → "SWOT 测高如何改进近岸海平面估计"，不能写成 "NASA 发布 SWOT 海平面产品"。
   例：原标题 "How to build an Argo quality-control pipeline" + 来源和正文明确是 IOC-UNESCO → "IOC-UNESCO 如何搭建 Argo 质控流程"，不能只写成缺主体的 "如何搭建 Argo 质控流程"。
6. 本条的动作和背景里的旧发布要分清：原文把发布写成过去的事（“At the Ocean Decade Conference, we launched …”“Last month we released …”“上个月我们发布了…”），本条是在讲用法、做演示或再次推广时，标题写介绍、演示或讲解，把发布交代成此前的事；不能写成“推出 / 发布 / 开放”，否则读者会当成今天的新闻。只有原文明确某项数据或能力是现在才开放或新增，才对那一项用对应动作。
   例：正文 "At the Ocean Decade Conference, we launched the atlas … See how to use it below" → "IOC-UNESCO 演示海洋十年大会发布的图集用法"，不能写成 "IOC-UNESCO 在大会推出图集"。
