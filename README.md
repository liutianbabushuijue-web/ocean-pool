# 海洋知识星球 · Ocean Knowledge Hub

把海洋机构、期刊与科研团队的公开更新，收进一个能自己保存、能继续改造的海洋阅读站。本版使用你提供的独立公开仓库 [ocean-pool](https://github.com/liutianbabushuijue-web/ocean-pool)：GitHub 保存代码和公开来源资料，本机浏览器负责阅读，不依赖 stepx。

这个仓库交付两部分：

| 部分 | 你能得到什么 | 需要什么 |
| --- | --- | --- |
| 中文阅读站：site/ | 中文标题与整理段落、原文链接、规则分类、搜索和本机收藏；输出中文 RSS 与原始来源 OPML | Python 3.11+；采集更新时需要网络，无模型密钥 |
| 完整引擎：engine/ | 继承并定制的 AIHOT 完整源码：后台、两次评分、中文写作、事件归组、热点和刊物 | Node >=24.22.1、PostgreSQL 17、模型服务与持续运行环境 |

**本轮已由聊天中的 AI 助手完成中文整理。** 当前221条资料都有中文标题与一段概括：44条依据论文摘要，66条依据来源节选，111条只有标题，已明确标注资料不足。采集器和阅读页不调用外部模型 API；这批中文结果不等于 AIHOT 的两次选稿评分或科学事实核验。新增或内容变化的资料进入待整理队列，不会自动翻译，详见 [中文整理怎么运行](docs/CHINESE_READING.md)。

## 先在自己电脑上看

1. 安装 Python 3.11 或更新版本。
2. 解压完整仓库，双击根目录的 **打开海洋阅读.cmd**。
3. 浏览器打开本机阅读站。窗口运行期间可阅读，关闭时在窗口按 Ctrl+C。

入口脚本立即打开已有资料，启动只监听本机的 http://127.0.0.1:8765/；重复打开会复用当前项目的阅读窗口。不是登录后台，也没有购买或付款步骤。想收取新资料时，双击 **更新订阅.cmd**，结束后刷新阅读页。如果某些来源暂时失败，页面保留能用的旧资料，并展示上次成功时间。不要直接双击 site/index.html：浏览器通常不允许它从本地文件读取 data.json。

## 保存到自己的 GitHub

目标仓库为 [liutianbabushuijue-web/ocean-pool](https://github.com/liutianbabushuijue-web/ocean-pool)，已核对为 **Public**，按你最新选择使用公开仓库。当前完整项目已在本机准备好，上传结果仍待远端验收；后续更新见 [GitHub 日常使用](docs/GITHUB_GUIDE.md)。本机文件夹名 ocean-knowledge-hub 可以保留，不影响远端仓库名称。

- 打开仓库的 **Actions → Refresh ocean sources → Run workflow**，可手动刷新。
- 首次上传及默认分支上的采集脚本、信源配置、测试或更新流程变更，也会触发一次更新；生成资料的写回不会循环触发。
- 更新流程保存到默认分支后，计划每6小时的第27分钟尝试运行；对应北京时间约 02:27、08:27、14:27、20:27。
- 生成的数据会由同一个官方 github-actions[bot] 提交回仓库，而不是随着临时运行机器消失。
- 当前阅读入口仍在本机，Pages 发布流程默认关闭；公开仓库不会自动发布阅读网站。后续需要网页分享时，再单独启用发布。

GitHub 的定时任务可能排队、延迟或被丢弃；公开仓库60天无活动还可能停用计划任务。它适合定期阅读资料，不承诺实时更新。[官方调度说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

目前交付的是可检查的本地仓库内容。是否已创建 GitHub 仓库、启用 Actions 或发布 Pages，以实际远端记录为准；文件里存在流程，不代表它已经在线运行。

## RSS 在哪里

先自己使用时，可以把 OPML 文件导入已有的订阅阅读器，直接订阅原始来源；不需要先发布本站。

RSS 既是输入，也可以是输出：

- **输入**：机构或期刊提供 RSS/Atom，本项目定期读取；Crossref 则是另一类接口输入。
- **输出**：site/feed.xml 把已完成中文整理的资料输出为一个中文订阅流，最多保留最新200条；待整理原文不会混入。
- **来源打包**：site/ocean-sources.opml 是来源目录，阅读器导入后可以直接订阅其中的 RSS 来源。OPML 本身不是新闻流，Crossref 和外部脚本源不会伪装成 RSS。

发布地址确定后，把实际站点地址设为 OCEAN_SITE_URL 或配置文件的 siteUrl，输出 RSS 才有正确的站点地址。未配置发布地址时，不把仓库里的 XML 文件宣称为已发布的线上订阅服务。详见 [RSS、信源与资料边界](docs/SOURCES_AND_RSS.md)。

## 卡兹克的 AIHOT，海洋版保留了什么

AIHOT 不是单纯“抓 RSS 再展示”。它的核心是采集之后的一整套编辑流程：预筛、独立评分两次、中文写作、归组为事件、按独立来源计算热点，再编排日报。每一步对应的源码、提示词和本版的调整，见 [从原版到海洋版的代码地图](docs/AIHOT_MAP.md)。

海洋定制已包含31个信源配置、8个领域类别、29份提示词。**配置数量不等于抓取成功数量**：其中5个中文 external 来源需要另外的采集任务。当前精选门槛仍是未校准起点，不能据此承诺选稿准确率。

上游是 [KKKKhazix/AIHOT](https://github.com/KKKKhazix/AIHOT)。上游开源的是引擎和18个公开示例来源，不包含原站真实信源名单、运营数据库或所有私有运营功能。engine/ 是继承的海洋定制快照，不声称与上游某一提交逐字相同。
